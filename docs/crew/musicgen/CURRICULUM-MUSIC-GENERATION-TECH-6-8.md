## Overview

Students design short musical patterns on a constrained step sequencer, iterate when a beat “doesn’t work,” then prove craft two ways: (1) play/export a song they made, (2) drive Visualizer standalone **and** with their song. Learning targets systems thinking, timing/pattern, iteration, and media CTE habits — not a band class and not an essay unit.

**Kid line:** *Open BertyBeatz. Make a beat. Fix it when it’s broken. Watch it become light. Share under your alias.*

---

## Essential questions

1. How is a beat a **system** (parts → pattern → whole)?  
2. What does it mean when a loop **doesn’t work** — and how do you fix it with **one** change?  
3. How can we **see** music without relying on sound alone?  
4. How do constraints (steps, sounds, volume, time) make better craft?

## Enduring understandings

- Patterns under limits are design, not random mash.  
- Fail → name why → one change → retry is tech work.  
- Visual feedback makes music accessible and checkable for everyone.  
- Fun (play loop · switch mode · save) and learning share the same craft.

## Day-by-day (40–45 min)

### Day 1 — Explore the grid
- **Objectives:** Place steps · play a loop · switch one visual mode (if linked) or hear loop clearly.  
- **Hook (3):** Teacher plays 4-on-the-floor vs random mash — “which is a pattern?”  
- **Teach (7):** Grid anatomy · Play/Pause · tap = on/off · mute OK.  
- **Work (22):** 4–8 steps · play · Assist OK.  
- **Close (5):** Oral “My beat does ___.”  
- **Formative:** Loop plays · at least 4 intentional steps.  
- **6/7/8:** 6 = 4 steps Assist · 7 = name kick vs snare · 8 = add one fill.  
- **Safety:** Volume · headphones · no yank cords · teacher gates speakers.  
- **Career:** Game audio / media tech — short line only.

### Day 2 — Generate a clear pattern
- **Objectives:** Build one clear pattern · name it.  
- **Hook:** Two saved aliases (demo) — spot the stronger pattern.  
- **Teach:** “Generate” = choose steps under limits · not paste a famous song.  
- **Work:** Craft 1 pattern · peer 30s listen (fair share).  
- **Close:** Write pattern name on ticket (alias).  
- **Formative:** Pattern recognizable on replay.  
- **Diff:** 6 starter row · 8 add third sound.  
- **Safety / career:** Same · recording engineer iterate takes.

### Day 3 — Constraints craft
- **Objectives:** Improve under tighter limits (step count / rows / no mash).  
- **Hook:** Same kit · 60s challenge — best clean loop.  
- **Teach:** Constraints make craft · systems tradeoff.  
- **Work:** Rebuild under posted constraint card.  
- **Close:** One tradeoff oral (“I cut steps so the kick stays clear”).  
- **Formative:** Constraint followed · loop still plays.  
- **Diff:** 6 given constraint · 8 invent one fair constraint for a peer.

### Day 4 — How not-working works
- **Objectives:** Break · name why · one change · retry (calm).  
- **Hook:** Teacher “breaks” a good loop on purpose.  
- **Teach:** Fail language — silent / early / late / muddy — no shame.  
- **Work:** Not-working ticket ×2 tries.  
- **Close:** Share one fix that worked.  
- **Formative:** Ticket complete · second play improved.  
- **ED:** Posted steps · Pause · short loops · escape Home.  
- **D/HH:** Ticket + visual pulse on play head · never sound-only success.

### Day 5 — Export the song
- **Objectives:** Export/save song file or handoff · alias only.  
- **Hook:** “Tomorrow Visualizer needs *your* song.”  
- **Teach:** Export path · alias · where file lives · FERPA — no legal names.  
- **Work:** Export · teacher spot-check open.  
- **Close:** Thumbs — file opens.  
- **Formative:** File exists · opens · is *their* pattern.  
- **Safety:** No personal PII in filenames.

### Day 6 — Visualizer standalone
- **Objectives:** Cold open Visualizer alone · demo beat / freeplay · switch mode.  
- **Hook:** Lights without “their” file yet.  
- **Teach:** Standalone door · mode card (kaleidoscope · bars · clouds · stars).  
- **Work:** Demo + freeplay · 3 modes · mute OK.  
- **Close:** Point to favorite mode + one word why.  
- **Formative:** Standalone prove PASS.  
- **Inclusion:** Viz not sound-only · reduced-motion · fat targets.

### Day 7 — Visualizer + kid song (dual prove)
- **Objectives:** Load kid song · viz follows · dual prove complete.  
- **Hook:** Standalone vs *their* track side-by-side.  
- **Teach:** Load/link · fail import → calm fallback to demo (never brick).  
- **Work:** Dual checklist · peer or teacher sign.  
- **Close:** Both doors checked.  
- **Formative:** **A + B PASS** required for full prove.  
- **Diff:** 6 teacher helps load once · 8 help a peer load (still own prove).

### Day 8 — Gallery / flex
- **Objectives:** Share under alias · optional remix · reflection one line.  
- **Hook:** Wall of aliases (no legal names).  
- **Work:** Gallery walk look/listen · optional remix · quiet extension.  
- **Close:** Payday / TechCash if live · pack headphones.  
- **Formative:** Presence + effort · optional remix star.  
- **Career:** Playlist curator / live visuals op — one sentence.

## Design brief (student)

**Challenge:** Generate a short original beat under class constraints. Export it. Prove Visualizer **standalone** and with **your** song.

**Limits:** Class sound kit only · step/column caps as posted · school volume · alias saves · `*.kulibert.net` tools only · no copyright full-song paste as “yours.”

**Prove:** Dual Visualizer doors + intentional pattern + one documented fix (ticket or oral).
